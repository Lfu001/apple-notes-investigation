# ラウンドトリップ実験

## 目的

`get_body` で取得した HTML をそのまま `set_body` で書き戻したときに、何が変わり何が保たれるかを観察する。また、`set_body` を複数回繰り返したときに不動点に収束するかも確認する。

本ドキュメントは生の観察記録である。観察から導かれる現在の事実は `docs/01-facts.md` に整理されている (重複する場合は `docs/01-facts.md` を一次ソースとする)。

## 方法

- 手順: `get_body` → `set_body` → `get_body` の結果を比較する。差分があれば、それをさらに `set_body` → `get_body` して、ラウンドトリップ 2 回目以降の収束を検査する。
- 環境: `docs/methods/environment.md` (iCloud の `HTMLTest` フォルダ、メモ.app 4.13、macOS 26.4.1)
- delay: 1.5〜2.0 秒
- ランナー: `scripts/py/roundtrip.py`, `scripts/py/multi_round.py`

## データ系統

| 系統 | プレフィックス | 作成方法 | 件数 |
|---|---|---|---|
| 合成メモ | `S` | AppleScript の `create_note` で HTML を投入 | 7 |
| GUI 由来メモ | `T` | メモ.appの GUI で書式を適用 | 17 (T01-T16 + T06b) |

## 主要観察

### 観察 1: HTML 表現の入出力は非対称

`get_body` と `set_body` の HTML 表現は非対称である。

| 段階 | 表現例 |
|---|---|
| GUI 由来の状態 (ラウンドトリップ 0 回目) | `<div><h1>Title</h1></div>`, `<div><h2>Heading</h2></div>`, `<font face="Helvetica">` 等のセマンティック HTML |
| `set_body` 通過後 (ラウンドトリップ 1 回目) | `<div><b><span style="font-size: 24px">Title</span></b></div>` 等。heading タグや font face が style 付き span に変換され、いくつかの要素が完全に消失する |
| `set_body` 通過後 (ラウンドトリップ 2 回目) | 1 回目と同じだが、各 heading 系の `<div>` 末尾に `<br>` が新たに付与される。これ以降は HTML レベルでの不動点となる |

### 観察 2: `set_body` は段落スタイル (タイトル / 見出し / 小見出し) を作成できない

ユーザー目視で確認 (2026-05-19):

`<h1>X</h1>` を `set_body` で送っても、`<div><b><span style="font-size: 24px">X</span></b></div>` を送っても、メモ.appはこれを「ボールド本文」として解釈する。

検証手順:

1. `<div><h1>X</h1></div>` で新規メモを作成すると、GUI 上では「ボールド本文」として表示される (タイトル段落ではなく、テーマサイズより大きい)。
2. `<div><h2>X</h2></div>` の場合、GUI 上では「ボールド本文」となる (見出しではなく、折りたたみ矢印もない)。
3. `<div><b>X</b></div>` の場合も、GUI 上では「ボールド本文」となる。

したがって、GUI 由来メモに対して `set_body` を 1 回でも呼んだ時点で、タイトル / 見出し / 小見出しの段落スタイルは永久に失われる。HTML レベルでは保存されているように見えるだけである。

より広範な探索は `experiments/paragraph-style-search.md` を参照。

### 観察 3: `set_body` は不可逆な情報損失を引き起こす

`set_body` を通すと以下の要素が完全に失われる。

| 要素 | GUI 表示 | `get_body` (ラウンドトリップ 0 回目) | `set_body` 後 |
|---|---|---|---|
| 画像 (`<img src=data:...>`) | 画像が表示される | base64 data URI で含まれる | 完全に消失する (`<div><br><br></div>` だけが残る) |
| PDF 添付 | PDF プレビューが表示される | body HTML に出てこない (`<br><br>` だけ) | 元から body にないため、添付参照が消える |
| ハイパーリンク (GUI 由来) | クリック可能なリンク | プレーンテキスト (リンクの痕跡なし) | URL が完全に消失する。新規作成は別経路で可能 (`experiments/hyperlink-attempts.md` を参照) |
| ハイライト (背景色) | 黄色の背景が表示される | 何も出てこない (プレーンテキスト) | 完全に消失する (`experiments/highlight-attempts.md` を参照) |
| チェックリストの状態 | チェック済みと未チェックの区別あり | `<ul><li>` (プレーンな箇条書きリストと同じ) | 区別マークなし |
| ブロック引用 | 引用スタイルで表示される | プレーン `<div>` (本文と区別不可) | 区別マークなし (`experiments/block-quote-attempts.md` を参照) |
| フォントファミリ (T11) | Helvetica 等 | `<font face="Helvetica">` | face 属性が消失する (size は維持される) |
| ソフトブレイク | 段落内改行 | 半角スペースに変換される (`line 1 line 2`) | スペースのまま |
| タイトル / 見出し / 小見出しの段落スタイル | テーマ依存のフォントサイズ、折りたたみ矢印 (`>`) 等 | `<h1>` / `<h2>` / `<h3>` (GUI 由来) | 段落スタイルが完全に失われ、ボールド本文となる |

### 観察 4: 保存される要素も多い

| 要素 | 結果 |
|---|---|
| 本文 (プレーン `<div>`) | 完全保存 |
| タイトル (`<h1>` 入力) | `<div><b><span style="font-size: 24px">...</span></b></div>` に変換され、HTML レベルで保存される |
| 見出し (`<h2>` 入力) | `<div><b><span style="font-size: 18px">...</span></b></div>` |
| 小見出し (`<h3>` 入力) | `<div><b>...</b></div>` (size 指定なし) |
| 等幅 | `<font face="Courier"><tt>...</tt></font>` で保存される (face は Courier 固定)。新規作成も可能 (5 タグから。`experiments/paragraph-style-search.md` を参照) |
| Bold / Italic / Underline / Strikethrough | `<b>`, `<i>`, `<u>`, `<strike>` で完全保存 |
| 箇条書きリスト (`<ul>`) | ネスト含めて完全保存 |
| ダッシュ付きリスト | `<ul class="Apple-dash-list">` で区別が保存される |
| 番号付きリスト (`<ol>`) | ネスト含めて完全保存 |
| 文字色 | `<font color="#XXXXXX">` で完全保存 |
| 任意のフォントサイズ | `<span style="font-size: 22px">` で保存される (face は失われるがサイズは保存される) |
| テーブル | `<object><table ...>...</table></object>` で完全保存 |

## 編集戦略への含意

- 安全な編集パターン: 画像 / 添付 / リンク / ハイライト / チェックリスト / ブロック引用 / タイトル / 見出し / 小見出しを含まないメモに対しては、2 回の正規化と編集と `set_body` の組み合わせで安全に編集できる。
- 編集前のチェック: `scripts/py/edit_recipe.py:check_safety()` で画像および添付を検出できる。
- 検出不可能な損失: リンク / ハイライト / チェックリスト / ブロック引用 / タイトル / 見出し / 小見出しは body HTML に痕跡が残らないため、事前検出は不可能である。

詳細は `docs/02-recipe.md` を参照。
